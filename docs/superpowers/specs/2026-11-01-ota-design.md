# Windows OTA 설계

상태: 사용자 승인 완료. 저장소 공개 전환과 설계대로 구현을 승인했고, 이후 검증·커밋·푸시·배포도 요청했다.

## 목적과 범위

공개 GitHub Releases의 Windows x64 설치 파일을 앱 안에서 확인·다운로드·검증·설치한다.
앱 시작 후 한 번 자동 확인하고, 설정에서 언제든 다시 확인한다. 다운로드와 설치는 사용자가 실행한다.
설치는 현재 추적을 종료하므로 적용 직전에 알린다. 설정·ROI·경기 기록은 기존 위치에 보존한다.
개발 실행, 데모, 스크린샷 스모크에서는 업데이트 네트워크와 설치를 사용하지 않는다.
실행 중인 사용자의 앱을 이번 개발 검증에서 종료하거나 업데이트하지 않는다.

## Approaches

1. **기존 Inno Setup 유지**: 현재 per-user 설치·경로·AppId를 그대로 이용한다. 작은 다운로드 모듈과
   앱 종료 뒤 실행되는 Windows 설치 보조 스크립트가 필요하다. 앞서 제안한 사용자 흐름에 맞는 권장안이다.
2. Electron 내장 autoUpdater: Windows에서는 Squirrel/MSIX 패키지로 전환해야 하므로 현재 설치기와 맞지 않는다.
3. electron-builder/electron-updater: 표준 NSIS 업데이트를 이용할 수 있지만 기존 빌드·설치기 마이그레이션이
   필요하다. 이번 요청에는 기존 경로를 보존하는 1안을 적용한다.

## 사용자 동작

- 설정의 정보 영역에 현재 버전, 업데이트 상태, 진행률, 상태에 맞는 버튼을 표시한다.
- 시작 후 약 10초에 최신 버전 존재 여부만 확인한다. 게임을 가리는 모달이나 자동 다운로드는 없다.
- `업데이트 확인` → `새 버전 다운로드` → `업데이트하고 재시작` 순서로 진행한다.
- 적용 직전 네이티브 확인창으로 추적 종료와 재실행을 알린다. 취소하면 앱과 엔진은 계속 동작한다.
- 오류는 설정에 한국어로 표시하며 재시도할 수 있다. 앱 종료 후 설치 실패는 다음 실행 때 결과와 로그를 알린다.
- 트레이에는 설정의 업데이트 영역으로 들어가는 항목을 둔다. 다운로드 중에는 중복 작업을 막는다.

## 다운로드와 검증

- 고정 저장소 `thsvkd/killfeed-lens`의 `/releases/latest`를 인증 없이 HTTPS로 조회한다.
- `vX.Y.Z` 정식 버전만 허용한다. 현재 버전 이하·draft·prerelease·잘못된 메타데이터는 설치하지 않는다.
- 해당 버전의 정확한 `killfeed-lens-X.Y.Z-setup.exe` 하나만 선택한다. GitHub가 제공한 SHA-256 digest와
  크기가 없으면 다운로드하지 않고 오류를 표시한다. 릴리스 URL·파일명을 고정 규칙으로 검증한다.
- 메타데이터와 다운로드에 시간·크기 제한을 둔다. 스트리밍으로 임시 파일에 쓰며, 완료 시 크기와 SHA-256을
  대조한 뒤 준비 완료로 전환한다. 실패한 부분 파일은 해당 작업 폴더에서만 제거한다.
- 다운로드는 HTTPS의 고정 GitHub 배포 호스트로만 리디렉션을 허용하며 횟수를 제한한다.
- 토큰을 앱에 넣지 않는다. 릴리스 설명을 HTML로 실행하지 않는다. 렌더러는 URL·경로·셸 명령을 지정할 수 없다.
- 이 무결성 검증은 기존의 코드 서명 미사용 정책을 대체하는 서명이 아니다. 같은 GitHub 계정의 릴리스와
  HTTPS를 신뢰하는 업데이트 경로이며, 자체 서명키·인증서·다른 배포 서버는 이번 범위에 추가하지 않는다.

## 종료·설치·복구

- 검증된 설치 파일과 고정 보조 스크립트, 작업별 JSON을 userData 하위 updates 폴더에 둔다.
- 작은 Windows GUI 실행 보조 프로그램이 숨겨진 PowerShell 프로세스를 소유한다. 실행 파일과 스크립트를
  작업 폴더로 복사해 설치 중 잠기지 않게 하고, 준비 확인 후 기존 quit()/stopEngine()으로 엔진을 정상 정리한다.
- 보조 프로세스는 기존 앱과 엔진 프로세스가 모두 끝나는 것을 제한 시간 동안 확인한 후에만 설치한다.
  다른 앱을 강제 종료하지 않는다. 종료가 확인되지 않으면 설치를 중단하고 결과를 기록한다.
- Inno Setup은 현재 사용자·현재 설치 경로로 실행한다. 자동 재부팅, 다른 프로그램 자동 종료, Restart Manager
  자동 재시작을 금지한다. 앱은 설치 성공 시 한 번만 다시 실행한다.
- 설치 직전에도 SHA-256을 대조한다. 설치 로그와 구조화된 결과를 남긴다. 실패를 성공으로 표시하지 않는다.
- 설치 파일은 앱 전체(Electron UI와 Python 엔진)를 함께 갱신한다. 사용자 데이터 폴더는 설치 대상이 아니다.

## 구현 단위와 검증

- `app/updater.js`: 버전·릴리스 검증, 상태, 다운로드, 적용 준비. Electron과 분리해 Node에서 시험한다.
- `app/install-update.ps1`: 종료 확인, 해시 검증, Inno 실행, 결과 기록, 재실행.
- `packaging/update-launcher.cs`: 부모 앱 종료 뒤에도 스크립트를 유지하는 Windows GUI 런처. Windows 기본
  .NET Framework 컴파일러로 빌드하며 별도 런타임을 내려받지 않는다.
- `app/main.js`, `preload.js`, `settings.*`: 허용 목록 IPC, 상태 표시, 사용자 동작과 종료 연결.
- `app/package.mjs`, `package.json`, CI/스모크: 테스트 파일 배포 제외, 업데이트 모듈·보조 스크립트 포함 확인.
- 전용 테스트는 잘못된 버전/URL/해시/크기, 중단·중복 다운로드, 재시도, IPC 범위, 설치 실패·종료 타임아웃을 다룬다.
- 보조 스크립트 검증은 격리된 임시 폴더와 가짜 설치/실행 프로세스만 사용한다. 실제 설치 경로·사용자 홈은 사용하지 않는다.
- 실제 공개 API의 익명 최신 버전 조회와 패키지 포함 여부도 확인한다. 검증 후 0.5.0을 커밋·푸시하고
  태그 CI로 GitHub Release를 배포한다. 게시한 실제 설치 파일의 OTA 다운로드·해시 검증까지 확인한다.
  사용자의 실행 중 설치판은 교체하지 않으며, 설치했다는 주장도 하지 않는다.
