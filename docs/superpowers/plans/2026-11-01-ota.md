# Windows OTA Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공개 GitHub Releases를 이용한 Windows 설치판 OTA를 기존 설치 구조에 추가한다.
**Architecture:** Node 업데이트 모듈이 릴리스·다운로드·무결성을 관리한다. Electron이 사용자 동작과 정상 종료를 연결하고 PowerShell 보조 프로세스가 종료 확인 뒤 기존 Inno 설치기를 실행한다.
**Tech Stack:** Electron 44.5.1, Node 내장 fetch/crypto/fs/child_process, Windows PowerShell 5.1, Inno Setup 6.
**Spec:** `docs/superpowers/specs/2026-11-01-ota-design.md` (사용자 승인 완료).

## Global Constraints

- 기존 AppId·per-user 설치·설정/ROI/경기 기록 위치를 유지한다. 외부 런타임 의존성은 추가하지 않는다.
- 저장소 공개 전환은 승인됐다. 전환과 익명 접근 확인 후 제품 구현을 진행한다.
- 개발/데모/스모크에서 업데이트 네트워크·설치가 비활성이다. 실제 실행 중 앱/게임/엔진을 검증 때문에 종료하지 않는다.
- 기존 `.gitignore`, HUD OCR 수정과 모든 미커밋 작업을 보존한다. 검증 후 커밋·푸시·0.5.0 태그 릴리스를 게시한다. 실행 중 설치판은 교체하지 않는다.
- 토큰 저장·임의 호스트/버전/파일 경로를 렌더러에서 받는 기능·자동 재부팅·다른 앱 강제 종료를 추가하지 않는다.

## Review Focus

- 훼손/절단/초과 크기 다운로드는 준비 완료로 표시하거나 실행하지 않는다.
- 중복 클릭·뒤늦은 IPC·요청 실패 뒤 재시도가 새 다운로드/설치를 중복 실행하지 않는다.
- 공백·한글이 포함된 설치 경로와 캐시 경로를 문자열 명령으로 해석하지 않는다.
- 엔진이나 앱 종료가 지연되면 파일 교체를 시작하지 않고 실패 결과를 보존한다.
- 보조 프로세스 준비 실패 시 기존 앱이 계속 살아 있고, 설치 실패는 다음 실행에서 사용자에게 보인다.

## Task 1: 공개 전환과 접근 확인

- [ ] 공식 Gitleaks 기본 규칙으로 현재 파일·전체 Git 이력을 검사하고 원격 도달 여부를 구분한다.
- [ ] 최신 설치판과 대표 portable를 실행 없이 추출하여 개인정보·크리덴셜·개인 DB/설정 포함 여부를 검사한다. 전체 12개 미검사 한계를 기록한다.
- [ ] `gh repo edit thsvkd/killfeed-lens --visibility public --accept-visibility-change-consequences` 실행.
- [ ] 인증 없는 HTTPS로 저장소 public, 최신 릴리스와 설치 파일 접근을 확인하고 준비 문서의 상태를 갱신한다.

## Task 2: 검증된 다운로드와 설치 보조 프로세스

**Files:** create `app/updater.js`, `app/updater.test.cjs`, `app/install-update.ps1`, `packaging/update-launcher.cs`.
**Interfaces:** `new Updater({ version, directory, launcherPath, onChange, fetchImpl? })`; `.state`; async `.check()`, `.download()`, `.install({ appExe, appPid, enginePid })`.
State: `{ status, version, percent, message }`, status = `idle/checking/current/available/downloading/ready/applying/error`.
`install()`은 보조 프로세스의 준비 확인 후 반환한다. Electron 호출자는 그 후 기존 `quit()`을 호출한다.

- [ ] Node 테스트에 버전 순서·draft/prerelease·파일명/URL/digest/size 검증, 실패 HTTP·잘못된 JSON을 추가하고 RED 확인.
- [ ] 고정 API/호스트·정식 버전 검증과 단일 작업 상태 전이를 구현하고 테스트 GREEN 확인.
- [ ] 스트리밍 크기·SHA256 일치/불일치, 중단·중복 요청·실패 후 재확인 테스트를 RED→GREEN으로 구현.
- [ ] 작업 폴더 안의 설치 파일·스크립트·JSON만 준비하고 설치 직전 재검증한다. 고정 PowerShell 실행 파일과 argv 배열로 보조 프로세스를 띄우고 준비 handshake를 확인한다.
- [ ] 보조 스크립트는 JSON의 main/engine PID 종료를 확인한 뒤 `/VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART /NOCLOSEAPPLICATIONS /NOFORCECLOSEAPPLICATIONS /NORESTARTAPPLICATIONS`와 현재 설치 경로·로그 경로로 Inno를 실행한다.
- [ ] 격리된 테스트 프로세스/폴더에서 종료 지연, 해시 불일치, 설치 실패, 공백·한글 경로, 성공 시 한 번 재실행과 실패 결과 보존을 검증한다. 실제 설치 경로는 사용하지 않는다.
- [ ] `node --test app/updater.test.cjs` 통과 및 PowerShell 구문 검사.

## Task 3: Electron UI·배포 통합

**Files:** modify `app/main.js`, `app/preload.js`, `app/settings.html`, `app/settings.js`, `app/settings.css`, `app/package.json`, `app/package.mjs`, `app/renderer.test.cjs`, relevant CI/docs.
**Interfaces:** allow-listed `update:check`, `update:download`, `update:install`; `settings:state.update`에 위 state를 포함한다. 메시지는 해당 설정 창에서만 수락한다.

- [ ] 설정 창 상태/버튼/진행률과 IPC 허용 목록을 숨김 Electron 창으로 RED→GREEN 검증한다.
- [ ] 설치판의 시작 후 10초 확인과 수동 동작을 연결한다. 재시작 확인창에서 취소하면 아무 프로세스도 종료하지 않는다.
- [ ] `Updater.install()` 준비 완료 후 기존 `quit()`으로 종료한다. 준비 실패 시 앱·엔진은 유지한다.
- [ ] 업데이트 결과를 다음 실행의 상태에 반영하고 업데이트 로그 폴더 열기를 고정 경로 허용 목록에 연결한다.
- [ ] 테스트 파일은 app.asar에서 제외하고 updater.js/install-update.ps1은 포함한다. 기존 release asset filename/digest 계약을 유지한다.
- [ ] npm 테스트와 CI에 업데이트 테스트를 연결한다. README·기존 handoff의 자동 업데이트 범위를 갱신한다.
- [ ] `npm test --prefix app`, 전체 pytest, 변경 파일 Ruff, `git diff --check`, 익명 릴리스 조회 및 패키지 포함 검사를 실행한다.
- [ ] 독립 최종 리뷰의 중요한 지적을 해결한 뒤 변경·검증·미설치/미게시 범위를 보고한다.

- [ ] 버전 0.5.0과 lockfile을 맞추고, 공개 바이너리의 서드파티 고지를 포함한다.
- [ ] 전체 테스트·lint/type/audit, 실제 패키징·스모크와 패키지 포함/제외 파일 검사를 통과한다.
- [ ] 변경 파일을 선택적으로 커밋한다. 기존 미추적 `500`과 로컬 자료를 포함하지 않는다.
- [ ] 원격 변경을 확인하고 main에 안전하게 통합·푸시한다. CI 통과 후 v0.5.0 태그를 push한다.
- [ ] 태그 릴리스 CI와 공개 Release 생성·자산 digest를 확인한다.
- [ ] 게시된 실제 설치 파일을 OTA 모듈로 익명 다운로드·검증해 ready 상태를 확인한다. 실제 사용자 설치판은 실행하지 않는다.
