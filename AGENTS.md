# Coding principles

- Make the smallest correct change that satisfies the request.
- Avoid unrelated refactors or cleanup.
- Match the existing codebase's conventions before introducing new patterns.
- Do not add speculative abstractions, features, or configurability.
- Verify changes with the narrowest relevant tests/checks.
- If ambiguity materially affects correctness or architecture, surface it;
  otherwise make a reasonable assumption and proceed.
