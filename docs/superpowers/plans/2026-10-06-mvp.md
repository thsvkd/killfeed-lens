# Killfeed Lens MVP Implementation Plan

**Goal:** Implement SPEC.md's replay-first, validation-capable Windows live prototype.
**Architecture:** Shared pixel pipeline behind capture, OCR, icon, parser and sink interfaces.
Persist observed events independently of post-match Telemetry. Use bounded capture queues.
**Tech stack:** Python 3.11+, OpenCV, NumPy, local ONNX OCR, SQLite, httpx, argparse, pytest.
**Spec:** [SPEC.md](../../../SPEC.md), [PRD.md](../../../PRD.md).

## Constraints and decisions

- Pixel-only OS capture; no process, packet, injection or input automation integration.
- Replay and screen share vision/parser/tracker. Unknown classification stays unknown.
- No real PUBG fixtures exist in this checkout; synthetic tests cannot establish RC accuracy.
- Initial ROI/threshold defaults require calibration and holdout tuning; label them provisional.
- OCR and icon models are local. No automatic uploads or runtime executable downloads.
- Keep API keys in PUBG_API_KEY only. Telemetry cannot modify live history.
- Work in this empty repository without altering the user's existing documents.
- User authorized autonomous implementation; do not insert plan approval handoffs.

## Review focus

- Persistent rows during ongoing background changes must emit only once.
- Simultaneous identical text rows must retain separate tracks; stale rows must expire.
- Bad frames must suspend event generation and reconnect with bounded retry.
- Match/time ambiguity must stop validation rather than produce misleading metrics.
- Model-free synthetic tests must never be represented as real PUBG accuracy evidence.
